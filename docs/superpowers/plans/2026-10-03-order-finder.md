# 주문·업무 찾기 구현 계획

**Goal:** 승인된 화면과 데이터 규칙으로 주문처 검색, 선택 북마크 가져오기, 최근 1년 매입 갱신을 구현한다.
**Architecture:** 최상위 App은 운영/주문 화면만 전환한다. 주문 기능은 order 폴더에 격리한다. 파싱·집계는 Web Worker, 검색은 상품별 요약을 사용한다. 로컬 캐시는 IndexedDB에 저장하며 Firebase가 설정된 배포에서는 공용 저장소를 사용한다.
**Tech Stack:** React/Vite/TypeScript/Firebase, SheetJS 0.20.3, Vitest.
**Spec:** 이 대화 outputs/주문·업무 찾기 데이터 검증 및 구현안.md 및 7개 인터뷰 답변.
**Execution:** 사용자의 ‘다음 작업 시작’ 지시에 따라 이 세션에서 직접 구현한다.

## Global Constraints
- 기본 화면 주문·업무 찾기, 운영 메뉴는 운영 화면 내부.
- 연락처 가져오기는 제외. 고정 10개+약국 전체 최근 30일 자동 5개.
- 미분류 즉시 검색, 양쪽 목록 상품은 용도별 두 결과, 적수는 필요할 때만 입력.
- 양수 입고 최근 3행, 1년 매입 기록 건수. 재업로드는 갱신 기간 집계 대체.
- 원본 데이터나 개인 북마크를 호스팅 자산에 넣지 않는다.

## Review Focus
- 소수 용량·제형·향·색상 보존, 서로 다른 제품의 오연결 방지.
- 기준일·1년 경계·미래/반품·같은 파일 재업로드.
- 적수 미입력 및 10병 박스 가격 계산.
- HTML 중첩 폴더, 선택하지 않은 개인 링크, 위험 URL.
- 여러 PC 동시 수정·공용 저장 실패와 복사 권한 거부.

## Tasks
1. 데이터 모델/정규화/집계/검색/가격/고정·자동 바로가기. core.test.ts의 실패를 확인하고 core.ts 구현.
2. 실제 XLS/XLSX 형식 파서와 Worker, 북마크 DOM 파서, 업로드 미리보기. 원본 33,905행과 493링크 검증.
3. IndexedDB 캐시와 Firestore 공용 저장, 상품 설정·링크·사용일 집계. 새 버전 게시 전 업로드 완료, 충돌 감지.
4. 최상위 탭, Chrome형 트리, 검색·상품 상세·관리·복원 화면. 1080×780과 실제 업로드 전체 흐름 검증.

## Verification
각 데이터 변경은 의미 있는 실패 테스트 후 구현. 전체 Vitest, TypeScript/Vite 빌드, 실제 자료 파싱, 브라우저 업로드·검색·적수·북마크 선택·재접속을 확인한다.
