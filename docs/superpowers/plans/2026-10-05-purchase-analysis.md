# 매입 분석 Implementation Plan

**Goal:** 기존 상단바에 세 번째 ‘매입 분석’ 탭을 추가하고, 저장 자료로 점검할 상품을 찾은 뒤 주문 화면으로 바로 연결한다.
**Architecture:** App에서 useOrderData를 한 번 공유한다. 분석 계산은 순수 함수, 화면은 별도 컴포넌트로 분리한다. 기존 주문 화면은 숨김 유지 방식으로 검색·스크롤 상태를 보존한다.
**Tech Stack:** 기존 React/TypeScript/Vite/Vitest, Pretendard 및 order.css 스타일. 추가 의존성 없음.
**Spec:** 인터뷰 확정: 가격 상승 / 매입처별 가격 / 자주 매입하는 품목. 구현 계획 실행까지 승인됨.

## Constraints and decisions
- 원본 자료와 Firebase 설정을 수정하지 않는 조회 기능.
- 가격 분석은 기준일 이하의 정상 매입, 최신 기록이 최근 1년 내인 상품에 적용. 이전 비교 기록의 날짜를 표시한다.
- 단위 확인 여부로 제외하지 않는다. 저장 가격과 설정 단위를 사용하며 단위 없으면 ‘단위’로 표시한다.
- 가격 변화는 다른 매입처도 포함하여 앞선 날짜의 직전 기록과 비교한다. 최근 매입 날짜순, 상승 기본 및 하락·동일·전체 필터. 매입처 변경 배지.
- 매입처별 가격은 최근 날짜순으로 3곳 표시하고 나머지는 펼친다. 직접 등록 가격은 ‘직접 등록 · 날짜 없음’으로 실제 기록 뒤에 표시한다.
- 거래처별 기록은 최대 최근 3건의 저장 자료이므로 전체 연간 금액/수량을 추정하지 않는다. 빈도는 수입 시 계산된 최근 1년 기록 수를 사용.
- 같은 baseId의 조제/판매 결과를 중복 집계하지 않는다. 직접 등록 가격은 가격 변화 계산과 매입 빈도에서 제외한다.
- 흑백, 진회색 선택 버튼, 얇은 회색 구분선, 좁은 여백과 모바일 가로 넘침 방지.

## Review focus
- 동일 매입이 조제/판매 데이터에 중복되어 빈도와 가격이 부풀려지지 않는가.
- 같은 날짜 기록에 대해 허위 시간 순서를 만들지 않는가(상승 비교는 다른 날짜만).
- 과거 매입 가격을 현재 판매 가격으로 보이지 않게 각 날짜를 표시하는가.
- 설정 누락/0수량/환입/미래 기록을 비교하지 않는가.
- 상품 연결 후 탭을 되돌아왔을 때 분석 조건이 유지되는가.
